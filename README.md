# Бот «Гости»

Общая картотека гостей для четырёх сотрудников в Telegram. Каждый сотрудник работает в личном чате с ботом: добавляет фотографию, телефон, имя и комментарий; ищет гостя по имени или телефону; меняет и удаляет карточки. Все сотрудники из списка доступа имеют одинаковые права на общую базу.

Проект подготовлен для запуска на Bothost. Токен, список сотрудников и путь к рабочей базе задаются в настройках хостинга; настоящие данные гостей хранятся отдельно от репозитория.

## Где хранится база

Для одного экземпляра бота и четырёх сотрудников достаточно SQLite: отдельный платный сервер базы на старте не нужен. Карточки, фотографии и посещения хранятся в одном файле `guests.sqlite3`. Telegram `file_id` используется для быстрой повторной отправки фото; сохранённые байты позволяют отправить его снова, если прежний идентификатор перестал работать.

## Время посещений

Откройте карточку через поиск. Когда гость приходит, нажмите **«Старт»**; когда уходит — **«Стоп»**. Завершённое посещение сохраняется и добавляется к общему времени. Карточка показывает текущий визит, общее время (включая идущий визит) и число завершённых визитов. **«Обновить время»** заново показывает актуальное значение; сообщение с карточкой само по секундам не меняется.

Таймер общий для всех сотрудников: один может начать посещение, другой — завершить. Повторное нажатие или старая кнопка не создают второй таймер и не останавливают следующее посещение. Редактирование данных гостя не сбрасывает время. **«История посещений»** показывает по пять визитов с началом, завершением и длительностью; даты отображаются по Москве (МСК).

Время начала и завершения хранится в UTC в базе. Перезапуск и обновление бота не прерывают отсчёт: посещение продолжается до нажатия «Стоп», в том числе во время остановки бота. Автоматического завершения или ограничения длительности нет. Каждый завершённый визит учитывается с точностью до целых секунд; часы могут превышать 24.

При первом обновлении старой базы бот сначала сохраняет её согласованную резервную копию в `data/backups/guests-before-visits-*.sqlite3`, затем добавляет таблицу посещений. Если копию создать не удалось, обновление схемы не начинается. Существующие карточки и фотографии сохраняются; их накопленное время начинается с нуля.

На Bothost задайте `DB_PATH=/app/data/guests.sqlite3`. Документация платформы описывает `/app/data` как постоянное хранилище между обновлениями. Перед вводом настоящих гостей обязательно проверим это в вашем аккаунте: создадим тестовую карточку, перезапустим бота и обновим код, затем снова найдём её. [Хранение базы](https://bothost.ru/docs/database-storage), [проверка сохранности после обновления](https://bothost.ru/docs/sqlite-data-lost).

Локально без настройки пути база находится в `data/guests.sqlite3`. Переменная `DB_PATH` имеет приоритет над `DATA_DIR`. Незавершённый ввод карточки хранится в памяти: после перезапуска его нужно начать заново. Уже сохранённые карточки остаются в базе.

## Подготовка доступа

1. В [@BotFather](https://t.me/BotFather) создайте нового бота командой `/newbot`. Сохраните токен отдельно от проекта.
2. Соберите числовые Telegram ID четырёх сотрудников, включая владельца. Имя `@username` для доступа не используется.
3. В `ALLOWED_USER_IDS` перечислите только эти ID через запятую, например `123456789,234567890,345678901,456789012` — замените все примерные числа настоящими.

Если ID пока неизвестны, при первом запуске временно поставьте `ALLOWED_USER_IDS=9007199254740992`. Это значение находится за пределами действительных Telegram ID по текущему [описанию Telegram API](https://core.telegram.org/bots/api#user), поэтому доступ к картотеке не получает никто. Каждый сотрудник пишет боту `/myid` в личном чате и передаёт владельцу полученное число. Затем замените временное значение четырьмя проверенными ID и перезапустите бота.

Команда `/myid` доступна в личном чате даже пользователю вне списка и показывает только его собственный ID. Остальные действия закрыты. В групповых чатах работа с карточками запрещена. Без токена или непустого корректного списка ID бот не запускается.

## Запуск на Bothost

1. Используйте репозиторий [MAYER-Ti/guest_registry_tg_bot](https://github.com/MAYER-Ti/guest_registry_tg_bot). Файлы `main.py`, `storage.py`, `config.py` и `requirements.txt` должны лежать в его корне.
2. В Bothost создайте Telegram-бота, подключите репозиторий и выберите его ветку. Для приватного репозитория настройте доступ по [инструкции Bothost](https://bothost.ru/docs/git-repository-access).
3. Укажите библиотеку aiogram и главный файл `main.py`. Можно включить «Использовать собственный Dockerfile» — он уже подготовлен под Python 3.12. При этом команду запуска задаёт Dockerfile. [Точка входа](https://bothost.ru/docs/main-file-entrypoint), [свой Dockerfile](https://bothost.ru/docs/custom-dockerfile).
4. Добавьте переменные окружения:

   | Имя | Значение |
   | --- | --- |
   | `BOT_TOKEN` | Токен вашего бота из @BotFather |
   | `ALLOWED_USER_IDS` | Четыре проверенных числовых ID через запятую |
   | `DB_PATH` | `/app/data/guests.sqlite3` |

5. Выполните деплой, проверьте журнал запуска и отправьте боту `/start`.
6. Проверьте сохранение тестовой карточки после перезапуска **и обновления из Git**, затем начинайте работу с настоящими карточками.

Бот получает сообщения через long polling. Домен и webhook для этого проекта не нужны. Запускайте только один экземпляр с одним токеном: одновременная работа локального бота и Bothost вызывает конфликт получения сообщений.

`.env.example` — образец переменных. Файл `.env` автоматически не читается: на Bothost используйте настройки окружения. В GitHub отправляется код. Токен, база с фотографиями и резервные копии исключены через `.gitignore`; перед загрузкой всё равно проверьте список файлов.

## Локальная проверка

Нужен Python 3.12 или новее. Из папки проекта:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
$env:BOT_TOKEN = "ВСТАВЬТЕ_ТОКЕН"
$env:ALLOWED_USER_IDS = "ВСТАВЬТЕ_СВОИ_ID_ЧЕРЕЗ_ЗАПЯТУЮ"
$env:DB_PATH = "data/guests.sqlite3"
.venv\Scripts\python main.py
```

Значения в примере нужно заменить. Не сохраняйте команду с настоящим токеном в общие инструкции или репозиторий.

Автоматические проверки:

```powershell
.venv\Scripts\python -m unittest discover -s tests -v
```

Проверки используют тестовую базу и подменённые ответы Telegram; настоящий токен им не нужен. Они не заменяют запуск на вашем Bothost и проверку в Telegram.

## Резервные копии и восстановление

Резервная копия содержит карточки, фотографии, историю посещений и активные таймеры. Скрипт использует механизм резервного копирования SQLite и подходит для работающего бота; токен ему не нужен:

```powershell
python backup.py backups/guests-2026-10-08.sqlite3
```

На Bothost выполните команду из каталога `/app`, указав файл внутри постоянного хранилища:

```text
python backup.py /app/data/backups/guests-2026-10-08.sqlite3
```

Выбирайте новое имя для каждой копии. Скрипт откажется перезаписать существующий файл и не создаст пустую базу, если исходная база не найдена. Регулярно скачивайте копии и храните их отдельно от аккаунта хостинга: копия на том же сервере не защищает от потери всего хранилища.

Для восстановления остановите бота, сохраните текущую базу и замените её выбранной копией по пути из `DB_PATH`. Старые служебные файлы `guests.sqlite3-wal` и `guests.sqlite3-shm`, если они остались после остановки, перенесите вместе со старой базой: их нельзя оставлять рядом с восстановленной копией. Запустите бота и проверьте карточку с фотографией. Восстановление возвращает всю картотеку к моменту копии.

Удаление убирает карточку, её посещения и активный таймер из действующей картотеки после подтверждения. Копии могут остаться в резервных файлах и ранее отправленных сообщениях Telegram. Обращайтесь с ними так же внимательно, как с основной базой, и удаляйте старые копии, когда они больше не нужны.

## Проверка перед рабочим запуском

- Все четыре сотрудника видят общую тестовую карточку и могут найти её по имени и телефону.
- Изменение фотографии, телефона, имени и комментария видно остальным сотрудникам.
- Отмена удаления оставляет карточку; подтверждённое удаление убирает её из поиска.
- Пользователь вне списка не получает карточки; групповой чат не получает карточки даже от разрешённого сотрудника.
- После перезапуска и обновления из Git тестовая карточка и фотография сохраняются.
- Таймер тестового гостя продолжает отсчёт после перезапуска и обновления из Git; другой сотрудник может завершить визит, после чего время видно в общей сумме и истории.
- Резервная копия успешно восстанавливается в отдельную тестовую базу.

Сначала проверяйте эти действия на вымышленных данных. Для отключения сотрудника уберите его ID из `ALLOWED_USER_IDS` и перезапустите бота.
